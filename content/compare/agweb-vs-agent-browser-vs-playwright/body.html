agweb vs agent-browser vs Playwright: what they're like to use

I read the three READMEs side by side, and the real split is not features but who the browser is for. One suits a Mac with many agents, one suits a portable CLI, and one suits teams already on Playwright.

agweb

agweb is one window that never takes focus, so several agents can work at once while you watch every tab on a dashboard. It is very new, with a few hundred GitHub stars, and it is deliberately narrow: WebKit on a Mac.

What I liked

  • Never steals your keyboard focus while agents work.
  • Replies say what changed, so agents skip extra snapshots.
  • One named profile keeps logins shared across agents.

What I didn't

  • WebKit only, so Chrome-only sites may misbehave.
  • No Chrome DevTools Protocol, so Playwright cannot attach.
  • macOS only, and the ad blocker cannot run uBlock scripts.

Best for: Mac users who run several coding agents at once and want to watch them.

agent-browser

agent-browser is a Vercel Labs project and the most starred of the three. Each command is one short shell call against a background daemon, and the same tool can attach to your own Chrome or hand off to a cloud browser provider.

What I liked

  • Short commands with refs like @e1 from compact snapshots.
  • Attach to running Chrome, or use Lightpanda or Obscura engines.
  • Cloud providers such as Browserbase and Kernel plug in.

What I didn't

  • Refs go stale after navigation, so you snapshot again.
  • A click fails if a banner covers the target.
  • Headless sessions close after an hour without commands.

Best for: teams that want one cross-platform CLI with room to move to cloud browsers.

Playwright CLI and MCP

Playwright comes in two shapes. The CLI plus skills suits coding agents, and the MCP server suits longer exploratory loops. Microsoft's own docs steer coding agents toward the CLI because it uses fewer tokens.

What I liked

  • Two entry points: a CLI with skills, and an MCP server.
  • Works with VS Code, Cursor, Claude Code and many MCP clients.
  • Headed mode, named sessions and an optional persistent profile.

What I didn't

  • The MCP server loads bigger schemas and snapshots into context.
  • In-memory profiles are lost when the browser closes.
  • Headless by default; headed mode opens a visible window.

Best for: teams already on Playwright who want agents on the same stack.

Which to choose

  • Choose agweb if you are on a Mac, run several agents and want a calm window you can watch.
  • Choose agent-browser if you need a cross-platform CLI and the option to move to a cloud browser.
  • Choose Playwright CLI or MCP if your team already uses Playwright and wants one stack for tests and agents.

If you need Chrome-only sites or the Chrome DevTools Protocol, skip the WebKit option.

FAQ

What is the best browser for coding agents?

It depends on your setup. agweb suits Macs running many agents, agent-browser suits a portable CLI on Chrome, and Playwright suits teams already using it.

Are agweb, agent-browser and Playwright free?

Yes. agweb is MIT licensed, and agent-browser and Playwright are Apache 2.0. Your costs are model tokens and any cloud browser you add.

Should I use Playwright MCP or Playwright CLI?

Microsoft says coding agents often do better with the CLI because it uses fewer tokens. It keeps MCP for longer exploratory loops with persistent state.

Does agweb work on Windows or Linux?

No. Its README says it needs macOS 15.4 or later and is built on WebKit.

Can an agent drive my own Chrome?

agent-browser can attach to a running Chrome over CDP with its --cdp or --auto-connect options. agweb cannot, since it uses WebKit.
