Browser Use vs Stagehand vs Skyvern: what they're like to use

All three put a language model in charge of a real browser. The difference is how each sees the page and how much control you keep: Browser Use and Stagehand work from the page structure, with Browser Use choosing each step and Stagehand following your script, while Skyvern reads screenshots to run whole workflows.

Browser Use

Browser Use is the quickest of the three to get moving: you give it a goal in plain words and the agent works out the clicks. The trade-off is predictability on long or messy tasks.

What I liked

  • MIT license and the largest community, at 120k GitHub stars.
  • Works with OpenAI, Anthropic, Google or local models through Ollama.
  • Lowest listed browser-hour rate, $0.02, before proxy and agent fees.

What I didn't

  • Long tasks can loop or stall instead of failing cleanly.
  • Cloud agent cost is model price plus 20%, so tasks vary.
  • Some sites with strong bot walls still block it.

Best for: Python teams that want an open agent that reaches goals with little scripting.

Stagehand

Stagehand feels like Playwright with an AI assist: you keep writing the steps, and act, extract and observe handle the parts where selectors would break. It gives you the most control of the three, and asks the most code of you.

What I liked

  • Plain page calls and AI steps mix in one script.
  • SDKs in TypeScript, Python and Go with matching methods.
  • Cached actions on Browserbase skip the model call entirely.

What I didn't

  • Caching and the model gateway need Browserbase-hosted browsers.
  • You write and maintain the flow yourself.
  • CAPTCHA solving starts on Browserbase's $20 plan.

Best for: developers who want repeatable scripts with AI only where pages change.

Skyvern

Skyvern reads the page from a screenshot, the way a person does, so it copes with forms and portals that change layout between runs. It is also the most complete product of the three, with a visual builder, a credential vault and 2FA handling next to the SDKs.

What I liked

  • Handles forms and popups that shift from run to run.
  • CAPTCHA solving, proxies and 2FA handling built into the cloud.
  • Cached actions cost half, at $0.015 each.

What I didn't

  • AGPL-3.0, and the cloud's anti-bot code is not in the repo.
  • Hobby's 30,000 credits cover about 1,000 actions.
  • No permanent free plan, only a 14-day trial.

Best for: operations teams automating forms and portals that change often, with less code.

Which to choose

  • Choose Browser Use if you want an open-source Python agent and the lowest browser-hour rate.
  • Choose Stagehand if you already write Playwright and want AI only where selectors break.
  • Choose Skyvern if you automate changing forms and portals and want CAPTCHA, proxies and 2FA built in.

Success rates vary a lot from site to site, so run your ten hardest real tasks on each before you commit.

FAQ

What is the difference between Browser Use and Stagehand?

Browser Use is an agent: you give it a goal and it decides each step. Stagehand is an SDK: you write the steps and use act, extract and observe where selectors would be fragile.

Is Skyvern open source?

Yes, under AGPL-3.0, and it self-hosts with pip or Docker Compose. Skyvern notes that its managed cloud's anti-bot measures are not in the open-source repo.

How much does an AI browser agent cost to run?

Browser time is cheap: $0.02 an hour on Browser Use Cloud, $0.20 effective on Browserbase Developer and $0.20 on Skyvern. Model tokens, or Skyvern's $0.03 per action, usually drive the bill.

Do they work with Claude Code or Cursor through MCP?

Stagehand does through Browserbase's hosted MCP server, and Skyvern supports MCP clients such as Claude Code and Cursor. Browser Use lists an MCP server on its site.

Can I run them without a cloud account?

Yes. All three run locally with your own browser and model key. The clouds add hosted browsers, proxies and CAPTCHA handling.
