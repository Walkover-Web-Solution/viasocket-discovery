What it's like to use Composio and Arcade

Both get an agent calling real apps, but they ask different questions first. Composio asks which tools your agent needs. Arcade asks who the agent is acting for. That split is what stood out to me, and most of what follows comes back to it.

Composio

Composio is the quicker start. You install the packages for your framework, add API keys to a .env file, create a session for a user ID and pass the session's tools to your agent. When a task needs an account, the agent shares a Connect Link, the user approves it and the agent carries on. The examples cover the OpenAI Agents SDK and the Claude Agent SDK in Python and TypeScript, and the Vercel AI SDK in TypeScript only, so check your framework is on that list before you commit.

You'll notice the quickstart is written for two audiences at once. A prompt for coding agents and rules for AI code generators sit beside the human walkthrough, so expect to skim past parts that are not for you.

Where I would spend my attention is auth. The rough edges that surface publicly lean towards connected accounts: tokens rejected on valid connections, a connect error page that hides the provider's own error, managed auth that lacks the scopes a tool needs, and a report of a request guard blocking tool execution for Gmail, Slack and Linear while the proxy still worked. These are individual reports, not a measure of how often they happen, but if something fails I would check the connection and its scopes before blaming the tool call.

The hosted model is the trade you are making. Community feedback on plugging in MCP servers through Composio has been warm, and the recurring worry is leaning on a remote server and on a third party that controls users' keys. That discussion was about an earlier version of the product, so ask how the current session model stores and scopes credentials.

The free plan is the real draw. 100,000 tool calls and 50,000 trigger events a month is plenty of room to build in. It pauses at the cap instead of billing overage, which keeps your bill safe but means a busy test week can stop work. Support starts as a portal on Hobby, with email from Pro.

Arcade

Arcade's quickstart is more about the user than the tool. You need an account, an API key and a user ID, then you install the client for Python, TypeScript or Java. A helper function checks whether a tool needs authorization, prints a link for the user and waits, and tools that need no authorization simply run. The worked example chains a Google News search, a Google Docs write and a Gmail send, which is a fair picture of an agent acting on someone's behalf.

That extra step buys the model Arcade is built around: authorization through your identity provider, so the agent acts as the signed-in user with each action scoped (per Arcade). If your agents will touch customers' or employees' accounts and someone will eventually ask who allowed what, that is the feature to weigh. If you only need an agent to call a few apps for yourself, it can feel like more ceremony than you need.

Public rough edges are harder to read, because the open reports I found sit on the framework repository rather than the hosted service. They touch the enterprise-flavoured parts: a Microsoft Entra ID authorization asking for a scope that cannot be changed, a blank Auth settings page in the dashboard, and CLI project commands that default to Arcade Cloud despite a saved host. If you plan to bring your own identity provider or host, test those paths early.

On cost, 2,000 free calls a month is a small allowance for testing an agent that loops, and the pricing page does not say what happens at the limit. At $0.01 per call on Team, the per-call rate is far above Composio's, though each vendor defines a call on its own terms, so ask what counts before you estimate a bill. Support runs from community on Free to next-business-day email on Team and 24/7 SLA-backed on Enterprise. Arcade also announced it acquired Smithery, an MCP registry and hosting platform, and its post announces no changes to Smithery's product or pricing.

What each says about the other

Each vendor's comparison page makes claims about the other, and I would treat them as marketing until you have run your own workload. Arcade says Composio typically acts with shared credentials, where Arcade acquires each user's OAuth tokens at runtime. Composio says Arcade's short-lived scoped tokens limit exposure, that Arcade shows strong token efficiency in specific workflows, and that it stores its own tokens with AES-256-GCM envelope encryption. Test token use and credential handling on your own agent before you believe either.

Which to choose

If you want an agent working across many apps quickly and a large free allowance, Composio is the easier start. If your agents act for real users and you need permission checks at the moment of action, identity-provider integration or an air-gapped deployment, Arcade is built for that. Both have free plans, and the per-call meters differ, so run each on your own workload before you decide.

FAQ

What is the main difference between Composio and Arcade?

Composio is a hosted catalog of app tools with managed auth. Arcade describes itself as an actions runtime that handles user authorization, policy and tool execution, with delegated per-user permissions.

Do Composio and Arcade both have a free plan?

Yes. Composio's Hobby plan includes 100,000 tool calls and 50,000 trigger events a month. Arcade's Free plan includes 2,000 tool calls a month.

Do both support MCP?

Yes. Composio exposes sessions through a hosted MCP endpoint. Arcade delivers its tools as MCP servers and lets you register your own.

Can I self-host Composio or Arcade?

Arcade's pricing page lists Arcade Cloud, your VPC or fully air-gapped deployment on Enterprise, and its docs describe self-hosting with Helm. Composio's pricing page does not list a self-hosted option.

Are Composio and Arcade open source?

Composio's SDK repository and Arcade's arcade-mcp framework are both MIT licensed. Arcade's prebuilt catalog is a hosted offering.
