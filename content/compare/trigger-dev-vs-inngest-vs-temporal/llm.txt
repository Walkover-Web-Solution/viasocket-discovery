## Short answer
Trigger.dev, Inngest and Temporal run long jobs and AI agent workflows that survive failures. Trigger.dev runs Apache-2.0 TypeScript tasks billed by compute second. ## Trigger.dev vs Inngest vs Temporal: what they're like to use
By Jatin Kashiv. All three keep a job running through crashes, retries and long waits. The real difference is where your code runs and what you pay for: compute time, steps or Actions.

### Trigger.dev
Trigger.dev feels the most like writing normal TypeScript: you define a task, deploy it, and it runs on Trigger.dev's machines with no timeouts. Billing follows compute time, so short jobs are cheap and long AI runs cost more.
What I liked:
- Waits longer than 5 seconds are checkpointed and not billed.
- Apache-2.0, with a self-hosting guide.
- Local dev mode and docs that users praise.
What I didn't:
- Code runs on Trigger.dev's machines unless you self-host.
- The v3 to v4 move meant a migration, with some v3 docs still around.
- A security incident disclosed on 1 November exposed environment variables for some organizations.
Best for: TypeScript teams running long AI or browser jobs who want them off their own servers.

### Inngest
Inngest wraps your existing functions in steps, so the code stays in your own app and infrastructure. Pricing is easy to forecast once you know your step count, because a run with five steps is six executions.
What I liked:
- Code stays in your own app and infrastructure.
- The largest free tier here: 50,000 executions a month.
- Concurrency and fairness controls built in.
What I didn't:
- Every step is billed, so long agent loops add up.
- The server is SSPL, with Apache-2.0 release delayed.
- Inngest does not guarantee support for self-hosted instances.
Best for: event-driven apps that want durable steps without moving code to another platform.

### Temporal
Temporal is the heavyweight: nine years in production by its own count, eight language SDKs and workflows that can wait for days. You run your own workers either way, and the determinism rules for workflow code take some learning.
What I liked:
- MIT license and SDKs in eight languages.
- Temporal names OpenAI, Replit and Cursor among its users.
- Cloud is pay as you go with no base fee.
What I didn't:
- Workflow code must follow strict determinism rules.
- Self-hosting a production cluster is real operations work.
- The Business support tier starts at $500 a month.
Best for: multi-language teams and long-running workflows where failure is expensive.

## Which to choose
- Choose Trigger.dev if you write TypeScript and want long jobs run for you, billed by compute time.
- Choose Inngest if you want durable steps inside your existing app and a large free tier.
- Choose Temporal if you need many languages, very long workflows or a mature engine you can self-host.
Model your own runs first: step count drives the bill on Inngest and Temporal, run time drives it on Trigger.dev.

## FAQ
Q: What is the difference between Trigger.dev and Inngest?
A: Trigger.dev runs your TypeScript tasks on its own machines and bills compute time. Inngest runs durable steps inside your own app and bills each run and each step as an execution.
Q: Is Temporal free?
A: The server is MIT and free to self-host. Temporal Cloud has no base fee, charges from $50 per million Actions and gives $150 in credits for 90 days.
Q: Can I self-host Inngest?
A: Yes, as a single binary, with Docker or a Helm chart. The default SQLite setup runs on one node only, scaling needs Postgres and Redis, and Inngest does not guarantee support for self-hosted instances.
Q: Which is best for AI agents?
A: Trigger.dev has durable chat agents and an MCP server, Inngest has the AgentKit framework and Temporal integrates with the OpenAI Agents SDK. Per-step billing on Inngest and Temporal adds up on long agent loops.
Q: What is the difference between Inngest and Temporal?
A: Inngest wraps functions in your own app as steps and bills executions. Temporal runs workflows on your own workers in eight languages, enforces determinism rules and bills Actions.
