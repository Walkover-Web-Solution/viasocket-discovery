Short answer: Mastra is an Apache 2.0 TypeScript framework with agents, workflows, memory, evals and a hosted platform, for teams that want one batteries-included toolkit. VoltAgent is an MIT TypeScript framework paired with the VoltOps console, for teams that want agent traces and operations beside their code. Both support MCP.

Both frameworks are free and open source. What you might pay for is the hosted side. Mastra Platform meters observability events, CPU time and storage. VoltOps charges by seat and by traces a month, with prompts, evals and RAG limits per plan.

What it's like to use Mastra and VoltAgent

Both get you from an empty folder to a working TypeScript agent quickly, and both treat observability as part of the job. The difference is the center of gravity. Mastra puts the framework first and adds Studio around it. VoltAgent puts the console in the loop from the first run.

Mastra

Mastra is the one that feels like a framework with a plan. You run npm create mastra@latest, get an agent harness with memory and a local workspace, and open Studio against it. The manual route is just as short: define a tool with createTool, give an Agent a provider/model string, and register both on a Mastra instance. What stood out to me is how much sits behind that one install: scorers, datasets, memory and a server. The trade is that you work the way it expects.

What I liked

  • One package covers agents, workflows, memory, evals and MCP in both directions.
  • Studio runs on localhost and brings traces, scorers, datasets and experiments into one place.
  • Memory has four layers, including observational memory that compresses old messages.
  • Deploys as a Hono server, to Vercel, Netlify or Cloudflare, or inside a Next.js app.
  • The core is Apache 2.0 and the hosted platform is optional.

What I didn't

  • It is opinionated, and designs that fall outside its patterns take more work.
  • Branching, rules-based flows feel clunky to express in workflows.
  • Memory does not work until you configure a storage provider.
  • Code under the ee/ directories is source-available, not Apache 2.0.

Best for: TypeScript teams that want a batteries-included framework with Studio, evals and memory in one place.

VoltAgent

VoltAgent starts from visibility. You run npm create voltagent-app@latest, answer a few prompts, and npm run dev starts a server on port 3141 with Swagger UI and a pointer to the VoltOps console. The starter includes an expense-approval workflow that auto-approves under $500 and suspends above it, which is a clear picture of how suspend and resume works. You'll notice the console does a lot of the explaining: you chat with the agent there and read the trace afterwards.

What I liked

  • The VoltOps console shows each run as a visual trace, with tool inputs and outputs.
  • The whole framework is MIT licensed.
  • Chain-style workflows with andAgent, andWhen, andAll and andRace, plus suspend and resume.
  • Supervisor and sub-agent teams are part of the core runtime.
  • Memory adapters range from LibSQL to PostgreSQL, Supabase and Cloudflare D1.

What I didn't

  • The community is smaller, with fewer stars and far fewer downloads than Mastra.
  • The free Developer plan allows 250 traces a month and 7 days of retention, which suits a trial, not a live app.
  • Type inference can get complex enough to need a @ts-ignore.
  • Managed memory, the Knowledge Base and VoltOps Deploy tie parts of the stack to the hosted console.
  • Docs are split across separate sites for evals, observability and deployment.

Best for: teams that want an MIT framework with a console that shows what the agent did, run by run.

Which to choose

If you want the broadest set of built-in primitives, a larger community and a local Studio for traces and evals, Mastra fits. If you want an MIT framework with chain-style workflows and a hosted or self-hosted console for traces, VoltAgent fits. Both frameworks are free, so build the same small agent in each before you decide on any hosted plan.

FAQ

What is the main difference between Mastra and VoltAgent?

Mastra is a framework with agents, workflows, memory, evals and its own Studio. VoltAgent describes itself as an agent engineering platform: an MIT framework paired with the VoltOps console for traces, evals, prompts and deployment.

Are Mastra and VoltAgent open source?

Yes. VoltAgent is MIT licensed. Mastra's core is Apache 2.0, while code in its ee/ directories is source-available under the Mastra Enterprise License.

Which has more GitHub stars?

Mastra has about 29.2k stars and VoltAgent about 10.9k. On npm, @mastra/core shows about 8.5 million monthly downloads against about 152,000 for @voltagent/core.

Do both support MCP as a client and a server?

Yes. Mastra has MCPClient and MCPServer over stdio and Streamable HTTP. VoltAgent has an MCP client over http, streamable-http, SSE and stdio, and an @voltagent/mcp-server package to expose your project.

Do I have to pay for the hosted platform?

No. Both frameworks run on your own infrastructure. Mastra Platform has a $0 Starter plan and a $250 Teams plan. VoltOps has a $0 Developer plan, then Core at $50 and Pro at $250 a month.

Where can I deploy each one?

Mastra builds a Hono server and has deployers for Vercel, Netlify and Cloudflare. VoltAgent runs as a Node server and has guides for Cloudflare Workers, Netlify Functions and VoltOps Deploy.
